Google AI App Workflow: From Design to Deployment

A practical flow for course projects: students create the product shape in Google Stitch, test Gemini behavior in AI Studio, implement in Antigravity, push to GitHub, and deploy through Vercel. CI/CD starts at GitHub.

Design AI Development CI/CD Edge

Optional advanced workflow

This document describes an optional advanced workflow. It is NOT required for the baseline assignment submission.

1

Google Stitch

Design screens, interaction flow, and visual direction first. Rationale: students see what they are building before engineering starts.

2

Google AI Studio

Test Gemini prompts, multimodal inputs, structured JSON output, and failure cases. Rationale: model behavior is easier to debug in isolation.

3

Antigravity

Build the real app: frontend, backend, database, auth, validation, environment variables, and tests. Rationale: this is where real implementation happens.

4

GitHub

Push branches, open pull requests, run CI checks, and review diffs. Rationale: the project becomes reproducible, collaborative, and auditable.

5

Vercel

Deploy previews for pull requests and production from main. Rationale: students get live URLs with little operations overhead.

Feedback loop: Vercel preview -> manual test -> GitHub issue or pull request comment -> Antigravity implementation -> GitHub push -> new Vercel preview. Optional Cloudflare layer: DNS, custom domain, WAF, cache rules, and TLS checks.

What counts as CI/CD?

GitHub checks and Vercel deployments are the CI/CD part. Stitch, AI Studio, and Antigravity are the design and development pipeline before CI/CD.

Is Cloudflare standard?

GitHub plus Vercel is already a very common baseline. Cloudflare is optional and useful when students should learn DNS, custom domains, security, or cache behavior.
